# 2026-10-19：刷新失败恢复与静默圆窗

用户截图显示 v0.1.6 的圆窗保留 65% 同时显示“连接失败”，要求减少刷新失败并不显示中文失败提示。

## 证据与根因边界

- 旧 Monitor 在失败时用中文错误替换成功时间；原 retry_delay 的首次失败等待 120 秒、连续失败最长 600 秒；Provider 对瞬时网络／超时直接返回，不能在同一刷新中恢复。这些行为均已由定向红灯捕获。
- 当前桌面捆绑 CLI 0.163.0-alpha.10.2 与 Homebrew CLI 0.155.1 的 initialize／account/rateLimits/read 分别约 1.08／1.56 秒成功；精确新包的真实查询也成功。未复现截图当次上游错误，不能断言已确定其网络根因。探针只保存耗时和错误类别，不保存账号、原始响应或凭据。

## 修改

- 同次刷新遇到网络／超时，间隔 200 ms 后重新连接一次；认证或协议错误不作此重试。单次初始化及额度请求共用 12 秒总时限；关闭仍可取消并回收精确子进程。
- 连续失败后以 3、10、30 秒重试，后续等待上限 60 秒。正常成功后的刷新周期继续使用原设置。
- 圆窗在失败、过期和后台刷新期间保留最近成功的额度及“更新 HH:mm”；从未成功显示 --% 和 --:--，不伪造新时间。错误状态及建议在设置页使用英文，诊断状态仍如实保留。圆环、配色、尺寸与菜单未改。
